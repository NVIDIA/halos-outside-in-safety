# Data schema

The viewer reads the bundle written by `srr.clip_logs` (in the
`regression-reporter` dir). One bundle = one multi-test run. Each multi-test
contains 5 scenarios; each scenario contains N clips.

## Top-level layout (one zip)

```
multi-test-YYYYMMDD-HHMMSS/
├── summary.md                    aggregator headline + per-run rollup + per-clip table
├── failures.json                 machine-readable list of FAIL clips
├── pss.log                       wall-time slice of PSF host syslog
├── balanced-10min/               one folder per scenario (5 total)
│   ├── reports/scn_*.md          per-clip aggregator reports
│   ├── reports/summary.md        scenario-level rollup
│   ├── scenes/scn_*.parquet      raw 30 Hz capture (not consumed by viewer)
│   ├── videos/scn_*.mp4          per-clip MP4 (not consumed by viewer; per-clip
│   │                             clip_logs/ has a copy)
│   ├── run-*.parquet             scenario-level run pool (not consumed)
│   └── clip_logs/                THIS is the viewer's data source
│       ├── index.json            per-scenario clip list with verdicts
│       └── scn_0000/
│           ├── manifest.json     ← clip metadata
│           ├── gt_positions.csv  ← GT positions panel
│           ├── psf_timeline.csv  ← PSF state panel
│           ├── ba_events.csv     ← BA events panel
│           ├── detections.csv    ← Detections panel      (3D runs only)
│           ├── tracker_state.csv ← Tracker-state panel   (3D runs only)
│           ├── ba_positions.csv  ← BA-positions panel    (3D + mdx-behavior only)
│           ├── pss_log.txt       ← (raw — not used by viewer; kept for QA)
│           ├── pss_log.jsonl     ← pss.log panel
│           └── video.mp4         ← <video> source
├── fast-20min/                   …
├── in-roi-5min/                  …
├── psf-clear-5min/               …
└── psf-edge-5min/                …
```

The viewer only reads files marked with `←` plus `summary.md` and the per-
scenario `clip_logs/index.json`.

The three Phase-2 CSVs (`detections`, `tracker_state`, `ba_positions`) are
written **only for 3D runs** — when the clip captured `mdx-bev` / `mdx-behavior`.
On 2D runs their `streams` keys are `null` and the viewer renders 4 panels; on a
full 3D run it renders 7.

## File schemas

### `summary.md`

Generated by `srr.aggregator`. Used by the viewer in two ways:

1. **Markdown render** — top section of the run browser page renders the
   headline + per-run rollup as nicely-styled HTML. The "Per-clip detail"
   section is stripped before rendering (duplicates the scenario tables).
2. **Headline parser** (`landing.js parseHeadline`) — pulls run-level
   metrics for the landing card:
   - `total clips: **N**`
   - `Mute correct%` + `n=` count
   - `Unmute correct%` + `n=` count
   - `ROI entries`, `TW IN`, `TW OUT` matched/total
   - `worst UNMUTE lag`, `worst MUTE lag` in ms
   - `mismatch frame totals — over-mute: N · under-mute: N`
3. **Per-clip table parser** (`manifest.js parsePerClipTable`) — pulls BA
   ROI / TW IN / TW OUT match counts for the per-scenario clip rows.

The markdown subset the renderer handles: H1–H4, bullet lists, tables
with alignment row, **bold**, `inline code`, `[links](url)`, blank-line
paragraph breaks. No code blocks, no images.

### `<scen>/clip_logs/index.json`

Per-scenario clip list. Written by `srr.clip_logs` after processing all
clips in a scenario.

```json
{
  "scenario": "fast-20min",
  "n_clips": 43,
  "pad_s": 5.0,
  "filter": { "scenarios": null, "fails_only": false },
  "clips": [
    {
      "clip_id": "scn_0000",
      "scenario": "fast-20min",
      "verdict": "PASS",
      "match_pct": 96.83,
      "path": "fast-20min/scn_0000/"
    },
    ...
  ]
}
```

### `<scen>/clip_logs/<clip>/manifest.json`

Per-clip metadata. Written by `srr.clip_logs` per clip.

```json
{
  "clip_id": "scn_0042",
  "scenario": "fast-20min",
  "wall_time_start": 1777835591.8780646,    // unix epoch — pair with pss_log timestamps
  "wall_time_end":   1777835619.6112196,
  "sim_time_start":  467.233337402,         // ROS sim clock seconds
  "sim_time_end":    477.799987792,
  "duration_s":      27.733155012,
  "padding_s":       5.0,                   // BA / pss padding outside the clip window
  "pad_wall_start":  1777835586.8780646,
  "pad_wall_end":    1777835624.6112196,
  "verdict":         "FAIL",                // PASS / NEAR / FAIL
  "match_pct":       0.12,
  "video":           "video.mp4",
  "streams": {
    "gt_positions":      "gt_positions.csv",
    "psf_timeline":      "psf_timeline.csv",
    "ba_events":         "ba_events.csv",
    "detections":        "detections.csv",     // 3D runs only; null on 2D
    "tracker_state":     "tracker_state.csv",  // 3D runs only; null on 2D
    "ba_positions":      "ba_positions.csv",   // 3D + mdx-behavior only; null otherwise
    "pss_log_text":      "pss_log.txt",
    "pss_log_structured":"pss_log.jsonl"
  },
  "counts": {
    "samples":         831,
    "ba_events":       40,
    "detector_frames": 47,                     // 3D runs only (unique BEV frames); 0 on 2D
    "pss_lines_raw":   165,
    "pss_lines_safety":165
  },
  "gt_summary": {
    "char_in_roi_pct":         100.0,
    "forklift_in_trailer_pct":  92.78,
    "expected_mute_pct":         0.0,
    "n_samples":               831
  }
}
```

The viewer:
- Uses `wall_time_start` as the video time-zero anchor (`videoToWall(t) = wall_time_start + t`).
- Surfaces verdict + match_pct + GT summary on the clip view header.
- Uses `padding_s` to flag rows with `wall_time < wall_time_start` as
  pre-clip padding (rendered with `before-clip` class).

### `<scen>/reports/<clip>.md`

Per-clip aggregator report. Written by `srr.aggregator render_clip_report`.
The viewer parses this with `loadClipMetrics` to enrich the run browser
table. Stable lines parsed:

| Line | Field |
|---|---|
| `**Verdict**: ❌ FAIL · match **0.12%**` | verdict + match_pct (also in manifest) |
| `- any character in ROI: **100.0%** of frames` | `char_in_roi_pct` |
| `- forklift in trailer (x>9.574): **92.78%**` | `fk_trailer_pct` |
| `- expected MUTE: **0.0%**` | `expected_mute_pct` |
| `- actual MUTE: **99.88%**` | `actual_mute_pct` |
| `- per-frame match rate: **0.12%** (FAIL)` | `match_pct` |
| `- **over-mute** (actual=mute, expected=unmute): 829 frames (99.76%)` | `over_mute_pct` |
| `- **under-mute** (actual=unmute, expected=mute): 0 frames (0.0%)` | `under_mute_pct` |

`Mute correct%` and `Unmute correct%` columns in the run browser table
are derived: `Mute correct% = (expected_mute% − under_mute%) / expected_mute% × 100`.
`n/a` when `expected_mute_pct == 0` (denominator is zero).

### `gt_positions.csv`

30 Hz sample of Isaac Sim ground truth + computed safety flags. Each row:

| Column | Type | Notes |
|---|---|---|
| `wall_time` | float (epoch sec) | primary sync key for all panels |
| `sim_time` | float (sec) | ROS `/clock` — Isaac sim time |
| `char_0_x`, `char_0_y` | float | character 0 world XY |
| `char_1_x`, `char_1_y` | float | character 1 |
| `char_2_x`, `char_2_y` | float | character 2 |
| `forklift_x`, `forklift_y` | float | forklift body world XY |
| `any_char_in_roi` | bool | computed: any character inside ROI polygon |
| `forklift_in_trailer` | bool | computed: `forklift_x > tw_x AND tw_y_min ≤ forklift_y ≤ tw_y_max` |
| `expected_mute` | bool | computed: `forklift_in_trailer AND NOT any_char_in_roi` |

ROI polygon + tripwire bounds come from VSS calibration (the SRR aggregator
uses the same calibration JSON the viewer doesn't read).

### `psf_timeline.csv`

30 Hz sample of PSF state, decoded from the JSON-string `psf_command` field
in the original parquet (which itself comes from the `/safety/command` ROS
topic, republished by comm-layer from PSF's OPC UA output).

| Column | Type | Notes |
|---|---|---|
| `wall_time` | float | sync key |
| `sim_time` | float | |
| `is_muted` | bool / null | from `/safety/is_muted` topic |
| `command_name` | str | `HEARTBEAT`, `MUTE (ALLOW OPERATION)`, `UNMUTE (PREVENT OPERATION)`, etc. |
| `status_name` | str | `Safety active + Alarm on`, `Safety muted - Loading allowed`, … |
| `source` | str | usually `opcua` |
| `is_alarm` | bool | |
| `sequence` | int | PSF monotonic command seqno |
| `ros_time` | str | ISO timestamp from comm-layer when message was relayed |

### `ba_events.csv`

VSS Kafka events from the run-level pool (`run-*.parquet`), filtered to
the clip window ± padding. One row per event-type emitted by an event;
multi-type events flatten across rows.

| Column | Type | Notes |
|---|---|---|
| `wall_time` | float | Kafka message timestamp (`_kafka_ts`) |
| `sim_time_offset` | float | seconds relative to `wall_time_start` (negative = pre-pad) |
| `in_clip` | bool | true if event landed inside the clip window proper |
| `event_type` | str | `ROI` (entry/inside zone) or `TW` (tripwire crossing) |
| `classes` | str | comma-separated, e.g. `Person`, `Forklift`, `Person,Forklift` |
| `direction` | str | `Right` (entering trailer) or `Left` (leaving) — TW only |
| `ids` | str | VSS event IDs, comma-separated |
| `create_time` | float / null | proto-extracted creation time (microsec→sec) when present |
| `raw_hex` | str | first 60 bytes of unparseable proto, hex-encoded — debugging fallback |

### `detections.csv`

**3D runs only** (`mdx-bev`). One row per detection per detector (BEV) frame,
each greedily matched to the nearest GT actor within a 1.5 m gate. Written by
`clip_logs._write_detections_csv`.

| Column | Type | Notes |
|---|---|---|
| `wall_time` | float (epoch sec) | sync key — the detector frame's arrival wall time |
| `bev_frame_id` | int | detector (BEV) frame id; groups detections in one frame |
| `track_id` | int / str | detector track id |
| `class` | str | detected class (e.g. `Person`, `Forklift`) |
| `x`, `y`, `z` | float | detection world position (`z` = 0.0 when the detector omits it) |
| `conf` | float / null | detector confidence when present |
| `matched_gt` | str | nearest GT actor within gate (`char_0`…`char_2`, `forklift`); `""` if none |
| `dist_m` | float / "" | distance to the matched GT, metres |
| `in_coverage` | bool | inside the detector coverage bbox (GT convex-hull + 2 m pad) |

### `tracker_state.csv`

**3D runs only.** One row per detector (BEV) frame: which detector `track_id`
is assigned to each GT actor over time (track-continuity view). Written by
`clip_logs._write_tracker_state_csv`.

| Column | Type | Notes |
|---|---|---|
| `wall_time` | float | sync key |
| `bev_frame_id` | int | detector frame id |
| `n_dets` | int | number of detections in this frame |
| `char_0_tid`, `char_1_tid`, `char_2_tid` | int / str / "" | track id matched to each character (`""` = unmatched this frame) |
| `forklift_tid` | int / str / "" | track id matched to the forklift |

### `ba_positions.csv`

**3D + `mdx-behavior` runs only.** One row per Behavior-Analytics-reported
position, de-duplicated across the 30 Hz oversampling, each matched to the
nearest GT actor within a 1.5 m gate — so the viewer can show BA localisation
accuracy alongside the raw detector. Written by `clip_logs._write_ba_positions_csv`.

| Column | Type | Notes |
|---|---|---|
| `wall_time` | float | sync key |
| `track_id` | int / str | BA track id |
| `x`, `y` | float / "" | BA-reported world position |
| `speed` | float / null | BA-reported speed when present |
| `direction` | str | BA-reported heading; `""` if absent |
| `matched_gt` | str | nearest GT actor within gate; `""` if none |
| `dist_m` | float / "" | distance to the matched GT (metres) — BA localisation error |

### `pss_log.jsonl`

Parsed pss.log slice — one JSON line per matching syslog entry. Filtered
to safety-relevant modules: `NVPSB_PSS_DAEMON`, `NVPSB_PSD_CLIENT`,
`nv_mdx_client`, `nv_atl_client`, `nvpss_daemon`. Other modules (CRON,
sshd, …) appear in `pss_log.txt` (raw) but not here.

```json
{"wall_time": 1777835587.414675,
 "iso": "2026-05-03T19:13:07.414675+00:00",
 "module": "NVPSB_PSS_DAEMON",
 "endpoint": "NVPSB_PSS_DAEMON",
 "msg": "PASSTHROUGH Safety Events. PassthroughEventId: 222608 ..."}
```

`endpoint` and `msg` are extracted from the original message body's
`Endpoint:` and `Data:` markers when present.

### `pss_log.txt`

Raw slice of `/var/log/pss.log` — every syslog line with ISO timestamp in
the clip wall_time window ± padding. Unfiltered. The viewer does NOT load
this; it's there for QA / human review (open in a text editor). The
viewer's pss.log panel uses `pss_log.jsonl` instead.

### `video.mp4`

Per-clip MP4. Encoded by VST replay — currently HEVC (H.265). Browsers
without HEVC support will spin forever on the `<video>` element. See
`troubleshooting.md` for the workaround (`transcode_to_h264.sh`).

The video starts at `t = 0` and runs for `manifest.duration_s` seconds.
`videoToWall(t) = manifest.wall_time_start + t`.
