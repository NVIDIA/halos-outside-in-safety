The Safety Core sits between AI Perception and the machine it protects. It reads perception
events from Kafka, checks that the cameras and the perception pipeline can still be trusted, and
sends a decision to the machine's controller over UDP. When it cannot trust its inputs, or loses
contact with one of its own components, it holds the machine in a safe state until an operator
releases it.

This guide is for someone who runs the Safety Core. It starts the Safety Core Docker container
with `docker run`, and every page gives commands you can run as written.

## Supported targets

| Target | Where the decision maker (SDM) runs | Applications |
| --- | --- | --- |
| x86-64 server with an NVIDIA GPU | Host CPU, inside the container | Forklift safety function, Proximity Monitoring, or two decision makers together |
| NVIDIA IGX Thor | CCPLEX, inside the container | Forklift safety function, Proximity Monitoring, or two decision makers together |
| NVIDIA IGX Thor | Functional Safety Island (container option `--sdm-on-fsi`) | Forklift safety function or Proximity Monitoring, one decision maker, 2D perception |

The operating system and driver versions for each target are listed in
[Prerequisites](/getting-started/prerequisites#software) in Getting Started.

## What runs where

The `nv-psf` container runs every Safety Core process except the command receiver and
`fsicom-agent`:

| Process | Where it runs |
| --- | --- |
| NvPSD Gateway (`nvpsd_gateway`), SEI daemon (`nvpss_daemon`), MDX client (`mdx_client`), SAIM (`safety_monitor`), PCM (`nv_perception_monitor`), SDM (`atl_sdm`, `proximity_sdm`) | Inside the `nv-psf` container |
| `fsicom-agent`, when the SDM runs on the Functional Safety Island | On the host; you start it yourself |
| Command receiver (`atl_sdm_cmd_receiver`, `proximity_sdm_cmd_receiver`) | On the host or another machine; you start it yourself |
